# Replace git submodules with a CSV manifest + auto-clone via git hooks

## Problem Statement

The catalog repository `docker-stack-collection` kept every project as a git
submodule. Submodules make it hard to work on stacks inside the shared repo and
are awkward for keeping catalog copies in sync between a laptop and a server.
We need:

1. The shared repo to track only a catalog (manifest) plus sync tooling; the
   projects themselves live next to it as ordinary independent repos, untracked
   by the catalog.
2. Periodic sync of the catalog between machines (a new project added on the
   server gets cloned on the laptop, and vice versa).
3. Sync with no manual script runs: after a plain `git pull`, missing projects
   are cloned automatically.

## Constraints

- Stacks remain independent git repos with their own `origin` (GitHub, `zyrakq/*`).
- Nested submodules **inside** each stack repo are left untouched.
- The `-stack` suffix is stripped from all repo directory names.
- The target category structure is the newer one from `docker/`
  (development-tools, devops, network-privacy, self-hosting); the old `stacks/`
  categories are dissolved.
- The "verified" project list = exactly the 37 former submodules, but since the
  user is not fully certain, they are marked `unverified`, not `completed`.
- Hook activation (`core.hooksPath`) is a mandatory per-machine step, documented
  in the README.

## Initial state (facts)

- `.gitmodules`: 37 submodules, all URLs of the form
  `https://github.com/zyrakq/<name>-stack.git`.
- `docker/` (untracked) contained 101 independent git repos in the new category
  structure; 32 of the 37 former submodules were present there, 5 were missing
  (sunshine, pi-hole, dnsmasq, vpn-server, bitcoin-core) and were cloned fresh.
- The remaining 69 repos were work-in-progress.
- Special case resolved during migration:
  `development-tools/registries/container-registries/distribution` was a
  container folder holding two repos: `servers/distribution-stack` (former
  submodule) and `clients/registry-admin-stack` (WIP).

## Approach

The catalog tracks only a CSV manifest (`stacks.csv`: path, url, status) plus
sync tooling (script + git hooks). Catalog sync between machines happens via
plain `git pull`/`git push`; cloning of missing repos happens automatically via
post-merge/post-checkout hooks.

## Architecture

```
docker-stack-collection/
  README.md              # mandatory step: git config core.hooksPath .githooks
  stacks.csv             # manifest: path,url,status (completed|incomplete|unverified)
  .gitattributes         # stacks.csv merge=union
  .gitignore             # generated by the sync script from the manifest
  .githooks/             # tracked hooks dir (contents of .git are NOT versioned)
    post-merge           # runs stack-sync.sh
    post-checkout        # runs stack-sync.sh
  scripts/
    stack-sync.sh        # idempotent: clones missing repos, regenerates .gitignore
    stack-sync.test.sh   # bash test suite
  stacks/
    development-tools/   # new structure (former docker/development-tools)
    devops/
    network-privacy/
    self-hosting/
    blockchain-nodes/    # new category, bitcoin-core only
    <...repos as ordinary clones, untracked by the catalog>
```

Why not hooks inside `.git/`: everything under `.git` is not versioned and does
not travel with clones. The convention is a tracked `.githooks/` directory plus
one-time local activation `git config core.hooksPath .githooks`.

## Manifest format

```csv
path,url,status
stacks/devops/monitoring/kibana,https://github.com/zyrakq/kibana-stack.git,unverified
stacks/devops/monitoring/grafana,https://github.com/zyrakq/grafana-stack.git,incomplete
```

- `status`: `unverified` — the 37 former submodules (likely finished, pending
  user confirmation); `incomplete` — the 69 WIP stacks; `completed` — set
  manually as the user verifies each stack.
- Status is informational: sync clones **every** row (both machines keep a full
  copy).
- `.gitattributes`: `stacks.csv merge=union` — independent row additions on two
  machines merge without conflicts.
- Row removal is manual only (union merge cannot delete lines).
- GitHub renders `.csv` files as a table natively, so the README just links to
  the file instead of duplicating the catalog.

## Sync mechanism

- `.githooks/stack-sync.sh`:
  1. Reads `stacks.csv`, clones repos that are missing locally. Does nothing
     else (no pull/push/merge inside stack repos — that stays manual).
  2. Regenerates the marker-delimited `.gitignore` section from manifest paths
     (the `*-stack/` pattern stopped working after the renames).
  3. Idempotent and safe to re-run.
- `.githooks/post-merge` and `.githooks/post-checkout` invoke the script.
- Per-machine activation (mandatory, README step after clone):
  `git config core.hooksPath .githooks`
- Bootstrap a new machine: `git clone … && cd docker-stack-collection &&
  git config core.hooksPath .githooks && .githooks/stack-sync.sh`
- After activation, any `git pull` that changes the manifest auto-clones the
  new stacks (post-merge).
- Limitation: post-merge fires only on real changes — but if the manifest did
  not change, there is nothing to clone.

## Migration (as executed)

1. Removed the 37 catalog submodules following the git-submodule-remove
   procedure: `git submodule deinit -f` → `git rm -f` → purge
   `.git/modules/<path>` → commit.
2. Moved `docker/` content into `stacks/` (4 categories), dissolved the
   `distribution` container folder into `servers/distribution` +
   `clients/registry-admin`.
3. Stripped the `-stack` suffix from all 101 repo directories.
4. Cloned the 5 missing former submodules into their new locations (sunshine →
   `self-hosting/media-streaming/sunshine`, pi-hole and dnsmasq →
   `network-privacy/dns/`, vpn-server → `network-privacy/vpn/`, bitcoin-core →
   `blockchain-nodes/bitcoin-core`).
5. Generated `stacks.csv`: 37 `unverified` rows (URLs from the old
   `.gitmodules`) + 69 `incomplete` rows (URLs from each repo's `origin`;
   3 repos have no remote → url `-`, skipped by sync with a warning).
6. Added `.githooks/stack-sync.sh`, `.githooks/*`, `.gitattributes`, generated
   `.gitignore`.
7. Rewrote the README for the new structure with the mandatory hooks step.

## Error Handling

- Repo without remote (`url = -`): skipped with a warning, no failure.
- Clone into an existing non-directory path: skipped with a warning.
- `merge=union` manifest: no conflicts when adding rows; duplicates are
  harmless (cloning is idempotent).
- The script never pushes/pulls/merges inside stack repos and never deletes
  anything.

## Testing Strategy

- Bash test suite `.githooks/stack-sync.test.sh`: clone missing, header/comment
  handling, idempotency (no re-clone, `.gitignore` unchanged), collision
  warning for non-directory paths.
- Real-tree checks: manifest has exactly 37 `unverified` + 69 `incomplete`
  rows; second sync run is a no-op; `git status` clean; hook smoke test on a
  fresh clone auto-clones a newly added row.
